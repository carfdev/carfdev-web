# Project guide

This repository is carfdev's portfolio, built with Astro, TypeScript, and Tailwind CSS. Read `README.md` for setup and commands, and `package.json` for the declared tool versions and scripts.

## Architecture

- `src/pages/` composes the home, about, contact, project list, project details, 404, and robots routes.
- `src/layouts/Layout.astro` owns the shared document structure, metadata, header, and footer.
- `src/components/` groups sections by page: `home`, `about`, `contact`, `projects`, and `project-detail`. Shared icons live in `icones`.
- `src/content.config.ts` loads and validates Markdown entries from `src/content/projects/`.
- `src/styles/global.css` contains Tailwind configuration, design tokens, and shared utilities.
- `astro.config.mjs` configures the site URL, fonts, Tailwind Vite plugin, and sitemap.
- `public/` contains static assets; `src/assets/` contains images processed by Astro.

## Working with project content

Inspect the collection schema before changing project entries or their consumers.

- The project list and `src/pages/projects/[slug].astro` consume the same collection and sort by `order`.
- The schema distinguishes `backend` entries with architecture nodes from `frontend` entries with a validated preview image and alt text.
- Project detail paths are generated by `getStaticPaths()` from collection IDs.
- Home page featured projects are selected by collection ID in `src/components/home/Code.astro`. Their names and links come from the collection; the featured selection and technology lists are curated separately.
- Repository and demo URLs are optional. Do not invent missing URLs or project information.

## Development

Use the Node.js and pnpm versions declared in `package.json`. When starting the dev server, use background mode:

```sh
pnpm astro dev --background
```

Manage it with:

```sh
pnpm astro dev status
pnpm astro dev logs
pnpm astro dev stop
```

The `pnpm dev` and `pnpm preview` scripts include `--host`, which exposes the server beyond localhost.

## Checks

Choose checks relevant to the change and report their actual results:

- `pnpm astro check` for Astro and TypeScript diagnostics.
- `pnpm build` for production build verification.
- `pnpm test` for unit tests, or `pnpm test:coverage` for the configured unit coverage.
- `pnpm test:integration` for composition and production-build contracts in a disposable copy.
- `pnpm test:e2e` for Chromium browser checks; install the Playwright browser as described in `README.md` first.
- `pnpm test:regression` for generated-page regression checks after a production build.
- `pnpm format:check` for project-wide formatting, or `pnpm exec prettier <changed-files> --check` for a focused check.

See `README.md` for the production Docker runtime checks, which also run in CI. Do not describe diagnostics or a successful build as a passing test suite.

## Existing conventions

- TypeScript extends Astro's strict configuration; `@/*` resolves to `src/*`.
- Components use Tailwind classes alongside shared tokens and utilities from `global.css`.
- Prettier uses the Astro and Tailwind plugins configured in `.prettierrc`.
- Existing UI copy and source comments are in English; preserve that language unless explicitly asked otherwise.
- The contact page uses links, not a form or submission endpoint.
